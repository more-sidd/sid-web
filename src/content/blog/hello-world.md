I have spent a lot of time building things that only ever existed as a repo and a
demo video. This is where I want to write the other half down — the reasoning, the
dead ends, and the parts that only make sense after they break.

## What goes here

Mostly three kinds of posts:

- **Build logs** — what I made, what went wrong, what I would do differently.
- **Notes** — smaller things: a paper I read, a tool that changed my workflow.
- **Photos** — from labs, field tests, and the occasional trip.

## Why not just a repo README

A README tells you how to run something. It does not tell you why the first three
versions did not work, and that second thing is usually more useful — both to
whoever reads this later and to me, six months from now, when I have forgotten.

> Writing is thinking. Everything else is note-taking.

Comments are open on every post, no account needed. If something here is wrong or
you have a better approach, say so.
